# Claude-workflow

> 模型接入与网关由你的环境决定；需要本地网关时，可自行评估 [Magpie](https://github.com/yetone/magpie) 等工具，本项目不要求特定网关。

Claude-workflow 是一套在 Claude Code 里使用多个模型协作开发的方式：你照常在同一个对话里提需求，当前会话理解目标、决定做法，把写代码、查资料、独立复核交给合适的模型，最后把改动和结果交给你。

它省去你手动切换模型、逐个重复交代背景的麻烦：实现和复核分开进行，你看得到改了哪些文件、测试实际跑出什么结果、还有哪些问题留着。用哪些模型由你的环境决定，不需要固定型号。

## 用起来是什么样

假设你有一个正在开发的项目，想加一个“导出配置”的功能。你在 Claude Code 里说清目标和验收，不需要指定谁来做：

```text
/multi-model-orchestration 给设置页加一个“导出配置”按钮，把当前设置导出成 JSON；补上对应测试，原有测试也要通过。
```

配置好分工后，大致会经历：

```text
澄清必要的问题
  → 适合该任务的模型改代码、补测试并实际运行
  → 另一个独立上下文复核改动、测试结果和边界
  → 当前会话汇总：改了哪些文件、测试输出、还没解决的问题
```

需要先了解外部资料时，也可以先让负责调研的模型带着来源查清，再进入实现。

## 几个使用案例

下面几个例子都从“你想做什么”出发，重点是你可以在 Claude Code 里怎么说。例子里的代理名是占位符，请换成你当前会话里实际可调用的名称；占位名不代表真实可用。

### 案例 A：开始一次协作开发

比如你想给已有项目的搜索框加上“最近搜索”。在 Claude Code 里发：

```text
/multi-model-orchestration 给现有项目加“最近搜索”：搜索框获得焦点时显示最近 5 条，选中后填入并触发搜索。
范围只改搜索相关组件和它的测试。验收是功能可用，原有搜索测试仍然通过。
实现完成后让另一个代理独立复核，再告诉我改了什么、测试结果和遗留项。
```

“最近搜索”只是例子，换成你自己的功能、文件和验收标准即可。必要时当前会话会先确认少量会影响做法的问题，再交给适合且可用的模型实现；完成后由另一个独立上下文复核改动、测试结果和边界，最后由当前会话把改动、实际测试结果和遗留问题交回给你。

### 案例 B：增加一个模型

假设你已经在自己的环境里接好了一个新模型，想让它参与日常实现。在 Claude Code 里可以这样说：

```text
/multi-model-orchestration 我已经接好了「新模型的准确名称」。
请为它建一个原生子代理，负责「想承担的工作」，再把它加入日常实现的候选。
如果已经有对应的原生代理，直接把那个名字加进名单。
```

把引号里的内容换成实际名称和该模型实际擅长的工作。已经接通的模型，建一个原生子代理或复用一个现成的，确认当前会话能调用后，加入日常实现的候选；已有代理只需改名单。模型接入和凭据仍由你的环境负责；本项目不代配路由或凭据。

### 案例 C：调整日常实现先找谁

用了一阵子后，你可能想换一下优先顺序。比如：

```text
/multi-model-orchestration 日常实现优先“代理 A”，其次“代理 B”；
难题保留原来的安排，复核保持独立。
```

把引号里的名字换成你工具目录里实际可调用的代理。配置好角色卡后，下次委托会按你确认的顺序选第一个适合且当前可用的候选。角色卡只影响“先找谁”，不改变模型本身，也不是执行失败后自动换模型重试的机制；未配置角色卡时不会自动产生这个顺序。

### 案例 D：把资料调研也加入分工

一开始你可能只安排了“谁写、谁复核”。后来有些任务需要先查清外部资料，可以这样说：

```text
/multi-model-orchestration 把资料调研也加入分工。用现在已经能调用的「某个代理」负责带来源的资料调查，
只做调研、不改代码，查完把结论和出处一起交回来。
```

之后遇到需要查资料的任务，当前会话会先把调研交给这个代理，再把带来源的结论交给实现或复核；前提是该代理已经接入、当前会话确实能调用。五类岗位职责（常规实现、困难实现、独立复核、资料调研、文字与审美）已经固定；每类交给谁、先后顺序由你在角色卡里按实际可用的代理配置，默认安装不预置人选，也不会自动选择候选。更细的说明见[角色卡参考](skills/multi-model-orchestration/references/role-cards.md)。

## 快速开始

需要 Claude Code、Bash 和 Python 3。安装文件在终端运行：

```bash
git clone https://github.com/liuyejinghong/Claude-workflow.git
cd Claude-workflow
./install.sh
```

默认只装编排 skill 和五岗纯职责定义，不创建模型代理、不写角色卡、不预置优先级。已有角色卡、代理和设置会保留，原有有效配置仍可使用。装完新开一个会话（或运行 `claude --continue`）。

全新配置且尚无用户绑定时，五类岗位（常规实现、困难实现、独立复核、资料调研、文字与审美）已有职责定义，但都处于未配置状态，还没有人选或先后顺序。需要时在 Claude Code 里运行：

```text
/multi-model-orchestration install
```

向导会先查看你当前已经接通、当前会话能调用的 agent 与模型和你的偏好，再给出候选与绑定预览。绑定写你确认的模型，或在你明确选择时写 `inherit`；不把维护者模型、示例或预设顺序当默认，确认后才写入。模型接入、订阅和凭据由你的环境负责。更完整的安装与配置说明见[安装参考](skills/multi-model-orchestration/references/installation.md)。

历史命令 `./install.sh --preset` 不再安装个人示例模型：执行会明确报错并退出，不写入任何文件。

模型选择由你的环境决定：先确认哪些模型已经接通、当前会话能调用，再按任务风险、成本和你的偏好确认绑定。本文不提供默认模型或固定顺序，也不把维护者环境里的搭配当通用推荐。公开模型与价格调研记录（2026-10-20 取样，历史资料，非默认推荐）见[模型调研](docs/research/popular-models-2026-10-20.md)。

## 查看运行状态

如果想看某次任务里有哪些模型在工作、各自占用了多少上下文、输出速度怎么样，可以加装独立的 [token-speed](mods/token-speed/README.md) 组件。它在输入框上方按代理显示模型、上下文占用和生成速率，装不装都不影响上面的使用。
