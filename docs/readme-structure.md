# 首页结构约定

这份文件说明根目录 README 的结构，供后续维护者改动时对照。写法依据是 [热门项目 README 调研](research/readme-patterns-2026-10-20.md)，这里只记结论。

## 固定结构

1. **H1 与开篇**：H1 后不放引言，直接进入项目介绍。Magpie 不在开屏出现，只在“快速开始”的前提里作为网关示例提一次。推荐本身即表明非必需，不另写免责声明，也不复述其营销或额度 failover 内容。
2. **项目介绍**：两三小段说清这是什么使用方式、对谁有用、解决什么日常问题、用了之后是什么效果；仍是在 Claude Code 里提需求，当前会话负责组织并交付结果。“当前会话”首次出现时用一句话定义。收益只保留减少手动切换与重复交代、实现和复核分开、交付改动和真实测试结果。适合谁写成两句：适合想让多个模型分工的人；没有 Claude 订阅也能用，只要能把其他模型接进 Claude Code。段末一行`直接安装：见 [快速开始](#快速开始)`。随后用“先认识三个词”引出岗位、代理、角色卡的定义。岗位给出六类中英对照（worker/engineer/reviewer/researcher/editor/architect）；代理说明与模型的绑定关系；角色卡说明可选与文件位置。三个词全文只在这里定义。不要从 JSON、key、安装边界或目录开始，也不要写心理推断式的铺垫。
3. **用起来是什么样**：开头一句说明装好后会多一个 `/multi-model-orchestration` 命令。再给一个具体需求，用短流程或短文展示“必要时澄清 → 适合该任务的代理实现并检查 → 独立复核 → 返回改动、测试结果和遗留项”。流程前不写“配置好分工后”这类前提，未配置角色卡时流程同样成立。“独立上下文”在流程后立即注解：没参与实现的代理，只看改动和测试结果。复核程度写明由当前会话按复杂度和风险安排。流程后给一份标明“示例、数字虚构”的回执（状态、改动、测试、遗留）；不虚构实测输出，也不承诺更快、更便宜、零 bug 或全自动并行。
4. **几个使用案例**（页面主体，3–4 个 H3）：开头交代案例 A 装好就能用，B–D 会改配置且先预览、确认后才写入。代理名占位符与“当前会话能调用”的口径在这里说一次，其余各例不再重复。每个例子围绕“想做什么 → 在 CC 里怎么说 → 会发生什么变化”，以自然语言对话为主；案例 A 展示限定范围与验收，不复述完整流程。至少覆盖：开始一次协作开发；增加一个模型；调整优先顺序；启用资料调研岗位。术语引用“先认识三个词”里的定义，不在例内重复定义；引号统一用全角双引号“”，不用直角引号。
5. **快速开始**：先写前提——Claude Code 里至少有一个能调用的模型；模型接入由用户环境负责，本项目不代配路由、订阅和凭据；三种常见情况（只有 Claude 订阅 → 所需 Claude 模型都可用时向导建议原生子代理；只有一个模型 → 可选 `inherit` 沿用当前会话模型；接入其他厂商 → 可用网关如 Magpie 或自己的方式）。再按“命令 → 装了什么（目标目录、备份、不改的文件）→ 重开生效 → 配置向导”的顺序写；`--preset` 的历史说明不进首页（CHANGELOG 已有）。`/multi-model-orchestration install` 称“配置向导”，并写明命令里的 install 指配置。向导只写“盘点当前会话可见的代理和已配置的模型，给出候选；候选不代表已接通，确认后写入”，不写成“已验证可用”。写明不配置也能用：当前会话按任务从能调用的代理里挑。配置角色卡是为了固定每类岗位先找谁。随后用一个小节按岗位给模型建议，固定格式：

   - **先讲类型**：每类岗位看重什么特点。开头写明当前会话不占岗位，用主模型负责规划和最终验收。常规实现看重速度、成本和工具调用稳定；困难实现推理和长任务能力优先，再按成本选择；独立复核宜用与实现者不同的模型、看重发现问题的能力；资料调研看重长上下文和检索能力；文字与审美拆开写——文案润色看重语言质量，界面审美反馈还要能看图（多模态）；架构与业务评审按需使用，看重第一性原理判断和对业务现状的理解，成本通常最高，不作每次改动的固定门禁。
   - **再给少量示例模型**：列表前声明“示例，不是要求，顺序不代表优先级”。只能取自 docs/research/ 已有归档里有依据的条目。模型名用官方完整版本名或官方 ID（如 `MiniMax-M3.1-Flash`、`deepseek-flash`），不用本地路由尾名（如 `deepseek-v4.1-flash`）、网关私有路由名或 `:free` 后缀；每个型号可带厂商与档位定位的短注（如“OpenAI 快速档”）；纯文本模型（如 `glm-5.3`）只放进文案润色，不放进要能看图的界面审美。不把维护者本机角色卡顺序、订阅或额度当建议。
   - **标注取样日期并链接调研归档**：同时链接 11-07 评分归档与 11-08 修正版，写明“11-08 对 11-07 有修正”。
   - **末尾声明这只是建议**：没有列表里的模型也能用，按能力挑同类；安装本身不带任何模型或顺序；用哪些代理、什么顺序由用户在配置向导里确认。

   免责集中说一次：模型接入由环境负责只在前提里说，模型建议的声明只在模型建议小节里说；首屏、案例和更多用法里不再重复。标题保持“快速开始”，其他文档的 `README.md#快速开始` 锚点依赖这个标题；位置仍放在案例之后。
6. **查看运行状态**：可选一小段介绍 token-speed 看什么，链接其 README；不展开插件安装命令与指标口径。
7. **更多用法**：按用户目标给少量链接；未实施的内部计划放列表末尾，用读者能懂的名称（如“改进计划（已评估，未采纳）”），不排在入口链接之前。末尾放两个组件版本、CHANGELOG 与 MIT 链接。维护首页的结构约定只给维护者，不在首页展示。

## 维护规则

- 首页先讲项目用途、收益和使用效果，再讲用户案例；不要按内部组件、代码结构或配置字段组织首页。
- 同一对象只用一个叫法：Claude Code 的子代理统称“代理”，六类岗位统称“六类岗位”（不写“六岗”“六类分工”），按岗位记录候选与顺序的配置统称“角色卡”。三个名称只在“先认识三个词”里各定义一次，英文键名对照也在这里给。候选统称“候选”，不写“人选”“名单”；“分工”只作动词用。
- 免责集中说一次：环境责任说明只在前提里，示例声明只在模型建议里，别处不重复。
- 增加模型：在用户自己的接入环境接通后（需要本地网关时可用 Magpie 等），为该模型建或复用一个代理。再把该模型加入某类岗位的候选；已有代理只需加入候选。首页建议里的模型一律用官方完整版本名或官方 ID（如 `MiniMax-M3.1-Flash`、`deepseek-flash`）；本地路由尾名（如 `deepseek-v4.1-flash`）、`:free` 之类后缀只留在 Magpie 示例或本地配置。不给假 model 路由串，不暗示本项目代接通模型。
- 建议模型更新：示例只能引用 docs/research/ 归档里已有的条目，随归档更新同步；不写归档里没有的价格、分数或能力结论，取样日期照归档标注；归档是历史快照，不代表现行配置；后续归档对早期归档有修正时，一并链接并写明修正关系。
- 新增岗位：当前分工固定为 worker / engineer / reviewer / researcher / editor / architect 六类，`check_role_names` 拒绝第七种。可用案例是“启用资料调研岗位并指定已能调用的代理”，不能写成在 JSON 里随便加 `tester` 就生效；自定义岗位边界最多一句加详细文档链接。
- 移除首页的完整 JSON、priority 字段解释、cards/verify 命令、排错三态、两层 effort、文件权限、原生定义路径、架构与调度算法，这些留在 references。旧“前 50 行内出现安装命令”的约束不再要求，故事顺序优先；首屏末尾的“直接安装”行满足想马上安装的读者。
- 例子里的代理名用占位或明确说明替换，不虚构截图、输出或性能数字；标明“示例、数字虚构”的回执可以给，此外不虚构实测输出；不写“零配置”“全自动”“最优”等空话。使用例只说明预期工作过程；免责不必逐例声明。
- 改完检查：章节顺序符合上述结构、相对链接与锚点存在、代码块闭合、案例仍以对话为主、全文没有直角引号。
