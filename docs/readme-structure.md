# 首页结构约定

这份文件说明根目录 README 的结构，供后续维护者改动时对照。写法依据是 [热门项目 README 调研](research/readme-patterns-2026-10-20.md)，这里只记结论。

## 固定结构

1. **H1 与推荐**：H1 后第一行用简短引用块推荐 [Magpie](https://github.com/yetone/magpie) 作为本地网关统一管理模型接入；推荐本身即表明非必需，不必另写免责声明，也不复述其营销或额度 failover 内容。
2. **项目介绍**：两小段说清这是什么使用方式、解决什么日常问题、用了之后是什么效果；仍是在 Claude Code 里提需求，当前会话负责组织并交付结果。收益只保留减少手动切换与重复交代、实现和复核分开、交付改动和真实测试结果。不要从 JSON、岗位名、key、安装边界或目录开始，也不要写心理推断式的铺垫。
3. **用起来是什么样**：给一个具体需求，用短流程或短文展示“必要时澄清 → 适合该任务的模型实现并检查 → 独立复核 → 返回改动、测试结果和遗留项”。不要求为例子额外加免责声明：假设的需求本身已表明是使用示例，但不能虚构实测输出，也不承诺更快、更便宜、零 bug 或全自动并行。
4. **几个使用案例**（页面主体，3–4 个 H3）：每个例子围绕“想做什么 → 在 CC 里怎么说 → 会发生什么变化”，以自然语言对话为主，不要求读者先学配置字段，也不要求每例重述完整流程。至少覆盖：开始一次协作开发；增加一个模型；调整优先顺序；把资料调研纳入分工。
5. **快速开始**：精简 clone/cd/./install.sh 与 `/multi-model-orchestration install`；写清五类分工已内置于编排，这一步只是给每类分工推荐模型人选（盘点已接好的模型、给出先后、预览后写入），不能写成“准备角色卡/先搭一套角色体系/写一张卡”；建议模型按“每个分工一段（加粗分工 + 这类工作的特点）、有序列表从前往后即优先级、每个模型附一句为什么适合这类分工”的格式，模型名必须带完整版本（如 `deepseek-v4.1-flash`），不得用不带版本的别名，来源 models.dev 与厂商官方页并标取样日期，禁止本地网关路由名和 `free` 后缀进首页，本地搭配只留在 Magpie 示例链接；说明模型需先接入且可调用，Magpie 可做这一步；详细安装外链。标题保持“快速开始”，其他文档的 `README.md#快速开始` 锚点依赖它；位置仍放在案例之后。
6. **查看运行状态**：可选一小段介绍 token-speed 看什么，链接其 README；不展开插件安装命令与指标口径。
7. **更多用法**：按用户目标给少量链接，末尾放两个组件版本、CHANGELOG 与 MIT 链接。维护首页的结构约定只给维护者，不在首页展示。

## 维护规则

- 首页先讲项目用途、收益和使用效果，再讲用户案例；不要按内部组件、代码结构或配置字段组织首页。
- 增加模型：在 Magpie 或用户自己的接入环境接通后，为该模型建或复用原生子代理，再把它加入某类分工的候选；已有代理只需加入名单。首页与建议表一律用官方完整模型名（如 `MiniMax-M3.1-Flash`），本地路由名、`:free` 之类后缀只留在 Magpie 示例或本地配置；不给假 model 路由串，不暗示本项目代接通模型。
- 新增岗位：当前分工固定为 worker / engineer / reviewer / researcher / editor 五类，`check_role_names` 拒绝第六种。可用案例是“把资料调研加入现有分工并指定已能调用的代理”，不能写成在 JSON 里随便加 `tester` 就生效；自定义岗位边界最多一句加详细文档链接。
- 移除首页的五岗表、完整 JSON、priority 字段解释、cards/verify 命令、排错三态、两层 effort、文件权限、原生定义路径、架构与调度算法，这些留在 references。旧“前 50 行内出现安装命令”的约束不再要求，故事顺序优先。
- 例子里的代理名用占位或明确说明替换，不虚构截图、输出或性能数字；不写“零配置”“全自动”“最优”等空话。使用例只说明预期工作过程，不虚构实测输出；免责不必逐例声明。
- 改完检查：章节顺序符合上述结构、相对链接存在、代码块闭合、案例仍以对话为主。
