# 多模型委托与编排

主控保留规划、根因判断、架构决策与最终验收；方案明确的实施任务委托执行。
选型以工具清单中各 agent 的 description 为准，无需为选型再读定义文件。用户指定模型优先；风险与合同先于速度。

## 调用协议

- Agent tool 用 `subagent_type` 选代理，不同时传 `model` / `effort`，以 agent 定义为准。
- Prompt 必须自包含，写全目标、背景、绝对路径、约束与可执行验收标准。
- 派发前只询问会实质改变目标或授权的真歧义；可调查的事实先查清，常规实施选择自行决定。
- 第一步指定 Read 一个文件确认工具可用；缺工具立即报告退出，不用 web 工具绕路。重派一次仍失败则主控接管。
- 可并行派发；修改文件不得重叠，或使用已获授权的 worktree 隔离。
- 审查 prompt 写明“直接审，不要调用 `/code-review` 等 skill”；需用审查 skill 时由主会话调用。

## Prompt 模板

```text
第一步 Read <指定绝对路径> 确认工具可用；缺工具立即报告退出，不用 web 工具绕路。
工作目录：<绝对路径>
目标：<完整任务与期望结果>
背景：<相关架构、已知根因、已确定的方案或合同>
涉及文件：<绝对路径列表>
约束：<范围边界、不可改的接口、依赖与风格要求>
验收标准：<最小合同测试或必要检查及其预期结果>
若为审查：直接审，不要调用 /code-review 等 skill。
完成后回报：改了哪些文件、实际命令输出、未解决的问题。
```

## 审查与返工

每个任务按以下顺序处理，不能跳过或调换：

1. 规格符合：是否恰好完成要求，未遗漏或超范围。
2. 代码质量：实现是否可靠、可维护。
3. 独立验收：主控实际执行最小合同测试与必要检查，不只信代理报告，不编造测试结果。

- 低风险机械修改由主控完成上述检查；常规逻辑有具体疑点或重要边界再派 Sol。
- 同一功能的多个子任务集成后，确需完整链路审查时派一次 Sol，不逐文件或逐结果重复审。
- 交易、持久化、并发、恢复、外部副作用安全保留 Sol 审查与主控最终验收。
- Sol 实现由主控独立验收，不用更弱模型作最终质量审批。
- 规格不符须返工并重新审查；产出有误先诊断，理解错则补 prompt 重派，仍不达标升级 `gpt-6.1-sol`。
- 任务过大则拆小，仍卡住再报告用户；不无限盲改。
- 必要检查通过后，仅在新改动、失败或具体疑点出现时扩大或重复验证。

## Workflow / ultracode

- 只有用户已选择 Workflow 时才编排或运行，不擅自启用工作流。
- `agent()` 的执行 stage 必须显式指定 `agentType`；省略会使用主会话模型。
- 选型依据仍是 agents 的 description；传 `agentType` 时不同时传 `model` / `effort`。
- 审查 stage 不逐结果强制派 Sol；需要完整链路审查时，同一功能集成后做一次。
- `gpt-6-astra` 只承担单个最难 stage，不进 fan-out。
- 裁决、综合、最终验收 stage 不写 `agentType`，由主控执行。

流程：并行执行 → 确认所有结果 → 集成与最小合同检查 → 必要时 Sol 审查 → 主控验收。失败或缺失结果须处理，不能过滤后继续。

运行示例见仓库 `examples/workflow-smoke-test.js`；它依赖 Workflow 运行时注入的 API，不能作为普通 Node.js 脚本运行。
